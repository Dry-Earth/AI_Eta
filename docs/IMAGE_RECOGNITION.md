# 本地图片识别

Eta 的 `read_image` 工具默认把图片作为视觉附件交给当前对话模型。如果对话模型在云端，
图片也就随之离开设备。开启「设置 → 图片识别」后，图片只发给本机或局域网内的识图服务，
对话模型拿到的是**文字描述**，图片本身不再进入对话请求。

## 使用方式

1. 在设置中打开「图片识别」，填写服务地址、路径与模型名。
2. 模型调用 `read_image` 时，Eta 把图片编码成 JPEG data URL，用 OpenAI 视觉协议
   `POST {base}{path}`（默认 `/v1/chat/completions`）请求一次。
3. 返回的 `choices[0].message.content` 作为工具结果文本交给模型，工具结果里显式标记
   `image_attached=false`、`local_vision=true` 和所用模型名。

兼容的服务（需支持 OpenAI 视觉消息格式）：

- Ollama：`http://127.0.0.1:11434` + `/v1/chat/completions`，模型如 `qwen2.5-vl`
- vLLM / SGLang：`http://192.168.1.10:8000` + `/v1/chat/completions`
- LocalAI、llama.cpp server（`--mmproj` 视觉投影）

## 为什么不会「逃逸到云端」

1. **地址白名单**：只接受环回、私有网段、链路本地、CGNAT、唯一本地 IPv6 与
   `*.local` / `*.lan` / `*.home.arpa`。填公网域名或公网 IP 会在保存时和调用时都被拒绝。
2. **失败即终止**：服务超时、返回错误、凭据无法解密时，工具直接返回错误结果；
   不会退回「把图片交给对话模型」的旧路径，也不会改发到其它服务。
3. **结果只含文字**：开启后工具结果不再携带图片附件，模型侧只看到描述文本。
4. **配置读不出也不放行**：读取配置失败时宁可报错也不按「未启用」处理。

要恢复「图片直接交给模型」的行为，需要手动关闭这个开关——这是显式操作，不会由失败自动触发。

## 自定义提示词

默认提示词要求客观描述场景、对象、可见文字与布局，并明确说明不确定的内容。
提示词可以在设置页替换，最多 4000 字；它会替换默认描述要求，不会与默认提示词拼接。

## 边界

- 只处理 `read_image` 工具读取的单张图片；聊天里手动附加的图片仍按原有附件链路发送给对话模型。
- 图片仍然受 12 MiB 上限与 JPEG 转码约束，超限会在本地失败。
- 识图请求使用独立的 `callTimeout`（120 秒），不参与对话模型的重试与降级。
